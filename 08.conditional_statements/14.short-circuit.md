## 14. Short-Circuit Evaluation

Python sometimes does not evaluate the entire condition.

### With `and`

```
print(False and 10 / 0)
```

Output:

```
False
```

No `ZeroDivisionError` occurs.

Why? The first value is False. Python knows the whole `and` result must be False.

### With `or`

```
print(True or 10 / 0)
```

Output:

```
True
```

No error occurs because the first value is already True.

### Interview Trick

```
x = 0if x != 0 and 10 / x > 1:    
print("A")else:    
print("B")
```

Output:

```
B
```

Python doesn't execute `10 / x` because `x != 0` is False.

This is a common way to prevent errors.

## 15. Operator Precedence in Conditions

Python evaluates some operators before others.

| Priority | Operators                        |
| -------- | -------------------------------- |
| Highest  | `()`                             |
| Next     | `**`                             |
| Next     | `*`, `/`, `//`, `%`              |
| Next     | `+`, `-`                         |
| Next     | Comparisons `<`, `>`, `==`, `!=` |
| Next     | `not`                            |
| Next     | `and`                            |
| Lowest   | `or`                             |

Example:

```
print(True or False and False)
```

Output:

```
True
```

Why?

First, `and` executes:

```
False and False  # False
```

Then:

```
True or False  # True
```

### Trick

When a condition is confusing, add parentheses to make the order clear.

```
if (age >= 18) and (has_license == True):   
 print("Can drive")
```
