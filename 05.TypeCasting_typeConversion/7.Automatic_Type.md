# 9. Automatic Type Conversion in Arithmetic

Python automatically converts compatible numeric types during arithmetic.

### Rule 1: int + float = float

```
print(10 + 2.5)  # 12.5
```

Why? Integer is promoted to float.

### Rule 2: int + int = int

```
print(10 + 5)  # 15
```

### Rule 3: float + float = float

```
print(2.5 + 1.5)  # 4.0
```

### Rule 4: bool behaves like int in arithmetic

```
print(True + True)    # 2print(True + 5)       # 6print(False + 10)     # 10
```

Why? `True = 1` and `False = 0` in numeric operations.

### Rule 5: int + string causes TypeError

```
print(10 + "20")
```

Output: `TypeError`

Why? Python does not automatically convert strings into numbers during addition.

Correct:

```
print(10 + int("20"))  # 30
```

### Rule 6: String + string performs concatenation

```
print("10" + "20")  # "1020"
```

Why? `+` joins two strings.

### Rule 7: String + int causes TypeError

```
print("10" + 20)
```

Correct:

```
print(int("10") + 20)  # 30print("10" + str(20))  # "1020"
```

### Rule 8: Multiplication with string

```
print("Hi" * 3)  # HiHiHiprint(3 * "Hi")  # HiHiHi
```

Why? String repetition is supported.

But:

```
print("Hi" * 2.5)  # TypeError
```

Why? String repetition requires an integer count.

### Rule 9: Division always returns float

```
print(10 / 2)  # 5.0print(9 / 2)   # 4.5
```

### Rule 10: Floor division

```
print(10 // 3)    # 3print(-10 // 3)   # -4
```

Why? Floor division rounds down towards negative infinity, not towards zero.

Compare:

```
print(int(-10 / 3))  # -3
print(-10 // 3)      # -4

Yes, floor division (//) in Python and mathematical definitions rounds down toward negative infinity, not toward zero.
• Positive numbers: Both truncation (toward zero) and floor division behave the same way (7 // 2 = 3).
• Negative numbers: Floor division moves further down the number line to the next smaller integer (more negative), whereas truncation chops off the decimal toward zero:
• -7 // 2 equals -4 (because -3.5 rounded down toward negative infinity is -4).
• Truncating -7 / 2 (-3.5) toward zero would give -3, which is not what // does.
```

### Rule 11: Modulus

```
print(10 % 3)   # 1
print(-10 % 3)  # 2
```

Why? Python's remainder follows the sign of the divisor.

In Python, the modulo operator (%) always takes the sign of the divisor (the number on the right)



1. 10 % 3

1. First, calculate the floor division: 10 // 3 = 3 (3.333 rounded down is 3).
2. Multiply by the divisor: 3 * 3 = 9.
3. Subtract from the dividend: 10 - 9 = 1.
• Result: 1

2. -10 % 3

1. First, calculate the floor division: -10 // 3 = -4 (since -3.333 rounded down toward negative infinity is -4).
2. Multiply by the divisor: 3 * -4 = -12.
3. Subtract from the dividend: -10 - (-12) which becomes -10 + 12 = 2.
• Result: 2

### Rule 12: Power

```
print(2 ** 3)  # 8
print(2 ** -1) # 0.5

The ** symbol in Python represents exponentiation (raising a base to a power).

2. The Math Behind It

When you include the minus sign, you are passing a negative exponent:
• Mathematically, any number raised to a negative exponent is equal to its reciprocal:
 2 ** -1 = 1/2 ** 1 => 1 / 2 => 0.5
• When Python divides 1 by 2, it outputs the float value 0.5.
```

# 10. Type Casting with input()

Frequently asked

Remember: `input()` always returns a string.

```
age = input("Enter age: ")
print(type(age))  # str
```

Even if the user enters `25`, Python stores `"25"`.

Correct:

```
age = int(input("Enter age: "))
print(age + 5)
```

If the user enters 25, output = 30.

For decimal input:

```
price = float(input("Enter price: "))
```

Interview question: What happens if the user enters `"hello"`?

```
age = int(input())
```

Output: `ValueError`

Why? `"hello"` is not a valid integer.
